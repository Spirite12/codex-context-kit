# Codex 远程部署操作

## 适用范围

用于用户明确授权 Codex 通过 SSH 操作已有的 1Panel、Docker、Node.js 和 MySQL 测试服务端。只处理用户指定项目，不扩大到系统更新、防火墙重配或其他站点。

## 凭证与连接

- 优先使用项目专用 Ed25519 密钥和 SSH 别名，不复用默认私钥。
- 私钥只保存在开发电脑，不上传服务器，不读取或输出私钥内容。
- 先用 `BatchMode=yes` 和 `IdentitiesOnly=yes` 做非交互连接验证。
- 输出中隐藏完整公网 IP、密码、AppSecret、Token、openid 和数据库连接串。
- 只读检查容器名、挂载目录、工作目录、启动命令和环境变量名称；不得输出环境变量值。

## 数据库迁移

按以下顺序执行，每一步成功后再继续：

1. 核对目标数据库和迁移文件；
2. 用带时间戳的文件执行迁移前备份，并将权限限制为仅管理员可读；
3. 把迁移文件上传到服务器临时目录；
4. 在目标 MySQL 容器中执行迁移；
5. 用 `SHOW TABLES`、`SHOW COLUMNS` 或等价只读语句核验；
6. 核验成功后删除服务器临时迁移文件，保留备份。

迁移命令不得在输出中展开数据库密码。不要因为迁移文件当前可重复执行，就跳过备份。

## Node.js 最小部署

先根据容器挂载和启动脚本判断运行时真正读取的文件。若依赖和启动配置未变化，仅部署已通过构建和测试的编译产物，不覆盖远端 `.env`、`node_modules` 或 1Panel 配置。

推荐流程：

1. 本地运行测试、构建和静态检查；
2. 将新 `dist` 上传到服务器唯一临时目录；
3. 检查入口文件和本次新增模块确实存在；
4. 将旧 `dist` 移到带时间戳的备份目录；
5. 将新 `dist` 移入应用挂载目录；
6. 重启指定容器；
7. 循环检查本机 `/health`，允许容器启动期间出现短暂连接失败；
8. 若重启或健康检查最终失败，恢复旧 `dist` 并再次启动；
9. 成功后保留旧版本备份，并报告备份位置。

健康检查至少同时证明应用和数据库正常。不得把“容器已创建”当作部署成功。

## 开发隧道

测试期可在 Windows 后台启动 SSH 本地端口转发，并加入：

- `ExitOnForwardFailure=yes`；
- `ServerAliveInterval=30`；
- `ServerAliveCountMax=3`；
- `BatchMode=yes`；
- 仅转发业务所需端口。

后台启动后，必须从开发电脑访问 `http://127.0.0.1:<本机端口>/health` 验证。若小程序提示登录失败，先检查本机健康接口；本机不通而 ECS 本机正常时，优先恢复隧道，不修改微信凭据或业务代码。

后台隧道会在电脑重启、SSH 进程退出或网络长时间中断后消失。向用户说明这是开发联调通道，不是正式上线入口。

## 操作边界与验收记录

- 用户仅要求诊断时，只做只读检查；明确授权部署后，才执行迁移、文件切换和容器重启。
- 删除服务器临时文件前确认绝对路径，禁止对宽泛目录执行递归删除。
- 每阶段记录目的、动作、预期结果和验收证据。
- 最低验收证据包括：迁移表结构、容器 `Up`、本机 `/health`、开发电脑 `/health`。
- 微信登录仍需单独验证 AppID 一致、`code2Session` 成功、用户与哈希会话正确落库。
