# 技术实践与安全边界

## 1. 适用架构

该 Skill 同时适用于纯小程序和全栈小程序。先识别现有架构，再选择链路，不为纯前端需求主动扩建服务端。

纯小程序典型链路：

```text
需求/设计 → 小程序前端 → 本地状态或微信原生能力 → 微信开发者工具 QA
```

全栈项目的开发链路应优先使用项目定义的本地或隔离测试环境：

```text
小程序 → 已确认的开发 API → 服务端 → 对应开发/测试数据库
```

生产链路通常为：

```text
正式小程序 → HTTPS 合法域名 → 反向代理/服务端 → 生产数据库
```

若项目使用云开发、Serverless、Kubernetes、托管数据库或其他架构，按实际项目处理，不机械套用 Node.js、SSH、Docker 或 1Panel。

## 2. 环境身份与连接方式

把“数据环境”和“连接方式”分开判断：

- 数据环境决定请求最终访问的是本地、隔离测试还是生产数据；
- 连接方式决定模拟器/手机如何到达对应 API，例如回环地址、局域网、受控隧道或正式 HTTPS 域名。

网络不通时先修连接方式，不得为了让请求成功而静默改连另一套数据环境。开发电脑或手机能访问 `/health` 只证明当前地址可达，不能单独证明数据库身份或微信外部能力已经就绪。

远端 SSH 隧道只在项目明确把目标登记为允许的开发/测试环境，且当前授权允许时使用；目标身份不明或可能是生产时停止，不把“已有 SSH 别名”当作测试环境证明。

服务端接口、数据库账号、迁移、字符集和数据验证的具体规则统一读取 `服务端与数据设计.md`，不在本文件重复维护。

## 3. 微信登录与会话

推荐流程：

1. 用户主动触发登录；
2. 小程序通过 `wx.login()` 获取一次性 code；
3. 服务端用对应 AppID/AppSecret 向微信换取身份；
4. 服务端创建或复用内部用户；
5. 签发高熵会话 Token；
6. 数据库仅保存不可逆 Token 摘要；
7. 明文 Token 只返回客户端并由客户端按项目规则保存；
8. 后续请求通过项目约定的鉴权方式访问。

`userId` 与微信身份标识是不同概念；AppSecret、session_key、访问令牌不得进入小程序包、普通日志或用户可见输出。

## 4. 微信 JSON 请求契约

使用 `wx.request` 发送带 JSON Content-Type 的非 GET 请求时，即使没有业务参数，也要遵循服务端契约发送明确请求体；常见做法是统一发送 `{}`，避免“声明 JSON 但 Body 为空”。

公共请求层应统一规范化请求体和请求头，避免每个接口单独修补。服务端返回 `204 No Content` 时不要声明需要 JSON Body；如果公共客户端固定解析 JSON，则使用明确的 JSON 成功响应并保持契约一致。

## 5. 开发、生产与授权边界

开发期可按项目规则使用测试号、本地 API、合法域名校验豁免或已确认的测试链路；正式发布前必须恢复生产域名、HTTPS、合法域名校验、最小权限、日志脱敏和项目要求的监控/备份。

微信上传、体验版、提审、正式发布、生产服务端部署和生产数据库写入属于不同外部动作；项目没有明确授权时不要因为前一阶段完成而自动继续。生产数据默认不用于开发造数、破坏性验证或故障复现。

## 6. 验收证据

保留与当前改动匹配的非敏感证据，例如：

| 层级 | 证据示例 |
| --- | --- |
| 前端 | 类型检查、编译、关键状态截图 |
| 服务端 | 自动测试、生产构建、受影响接口验证 |
| 数据库 | 迁移前后结构或版本记录，不展示无关业务数据 |
| 环境 | 当前模式、目标身份与健康检查结果 |
| 微信能力 | 字段契约、配置存在性、平台调用结果 |
| QA | 用例结果、console/network 和关键截图 |
| 发布 | 实际上传/审核/部署/正式发布状态 |

证据只证明对应层级。容器 Up、HTTP 200、模拟器正常或代码已合并，都不能单独证明整个版本已经正式发布。
