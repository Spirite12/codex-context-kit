# 微信能力与发布检查

## 适用范围

用于订阅消息、模板消息、广告、支付、隐私权限、手机号/位置等微信平台能力，以及其他“代码之外还需要平台配置或服务端运行配置”的功能。

目标是把两类问题分开：

1. **设计契约**：平台能力是否能表达当前业务需求；
2. **运行就绪**：目标发布环境是否真的配置并启用了该能力。

## 新增或更换模板时的字段门禁

在写业务发送代码前，为每个业务字段建立“业务值 → 微信模板字段”的映射，并核对：

- 字段类型和允许格式；
- 最大长度；
- 整数/小数精度和可接受范围；
- 日期、时间、金额等格式限制；
- 枚举或固定前缀要求；
- 单位是否能完整保留；
- 典型值、最小值、最大值和历史兼容值。

若合法业务值无法在模板字段中无损表达，应优先更换模板或重新确认产品展示方案。不得为了通过平台限制而静默截断剂量、金额等数值，或删除会改变含义的单位。

历史模板已经存在且无法立即迁移时，可以保留明确的兼容分支，但新模板必须重新通过上述门禁，不能复制历史限制。

## 配置契约

对每项微信外部能力，至少核对：

- 客户端使用的模板/能力标识；
- 服务端需要的环境变量或安全配置；
- 平台后台实际启用的模板、权限或域名；
- 服务进程是否真正加载了对应配置；
- 调度器、发送器、回调、资源或队列是否启用；
- 必要的隐私政策、权限声明和用户触发方式是否匹配。

示例配置文件应列出所有必需键，但不写秘密值。运行时核验配置存在性时只输出“已配置/缺失/不匹配”，不要打印 AppSecret、Token、数据库密码或完整连接串。

## 什么时候检查

### 开发与合并前

只做静态检查：

- 代码是否声明了所需配置；
- 示例配置是否完整；
- 模板字段契约是否通过；
- 自动测试是否覆盖平台成功、拒绝和错误响应；
- 项目文档是否记录新增能力依赖。

“合并到 main”本身不授权连接生产环境。

### 进入正式发布流程

在项目定义的发布就绪阶段执行目标环境检查；只有用户授权访问该目标时才读取远端状态。至少确认本版本依赖的能力没有出现“客户端可见、服务端未配置”或“服务进程正常但对应发送器未启动”的情况。

如果该能力是本版本必需功能，缺配置或无法核验时发布就绪检查失败；如果项目明确将其作为可选且当前禁用，应把“禁用”作为显式状态，而不是误报为可用。

用户也可以单独要求执行一次功能就绪检查，不必进入完整发布流程。

## 发布后动作

正式发布、通知用户、批量发送消息、清理旧模板等是不同动作。只有项目流程明确包含并且用户授权时才执行。

如果项目规定正式发布成功后需要询问是否发送版本通知或其他批量消息：

1. 先核验正式发布确实成功；
2. 只在该项目实际存在对应能力时询问；
3. 用户确认后才触发；
4. 用户拒绝或稍后处理时记录为未执行/待办；
5. 不因服务端部署、代码上传、审核通过或 Git 合并自动触发。

## 失败处理

平台字段不匹配、生产配置缺失、调度器未启用或后台权限未生效时，优先修正当前层级；不要通过修改无关业务逻辑、跳过配置核验或切换环境来掩盖问题。
