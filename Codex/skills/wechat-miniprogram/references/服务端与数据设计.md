# 服务端与数据设计

## 数据契约

- 设计字段前先读取现有技术文档、服务端模型、历史迁移和本地可用结构，不根据常见命名猜测主键、外键或字段。
- 本地事实不足、互相冲突或疑似过期时，只有在目标环境身份明确且用户允许只读检查时才访问远端结构；未获允许时不要连接远端。
- 明确请求、响应、错误码、鉴权、时区和幂等语义；前后端共享同一业务含义。
- 服务端重复验证类型、范围、步长、日期和状态转换，不信任前端输入。
- 单用户当前配置优先单行保存并覆盖；只有需求明确时才增加历史表。
- 自然日业务显式指定时区，日期字段优先使用明确的日期语义。
- 返回可复用的结构化数据，避免把展示文案作为唯一业务数据。
- 删除或改变产品规则时，同步清理状态枚举、计算分支、测试断言和正式事实文档，不能只隐藏前端文字。

## 实现顺序

1. 核对技术文档、代码、接口、配置和本地迁移；
2. 定义服务接口、错误语义和数据库契约；
3. 编写最小迁移和仓储变更；
4. 实现业务校验、鉴权和状态计算；
5. 接入应用启动入口；
6. 编写受影响的服务/路由/仓储测试；
7. 执行相关类型检查、自动测试和生产构建；
8. 只有任务需要且获得目标环境授权时，才执行远端备份、迁移、部署、结构核验和健康检查。

## 迁移与字符集

- 迁移进入版本控制，已执行迁移不原地重写；修正使用新的迁移。
- 执行前核对目标数据库身份和历史迁移完整性，不能只检查本次新增文件。
- 使用 MySQL 客户端处理包含中文或其他非 ASCII 数据的迁移时，显式使用项目要求的 `utf8mb4` 连接字符集；数据写入前声明正确连接字符集，执行后抽查实际文本或等价字节证据。
- 发现乱码、错误编码或缺失历史迁移时先停止后续部署，保留备份并按项目规则修复；应用健康检查不能替代迁移完整性证明。

## 安全规则

- AppSecret、数据库密码、会话密钥和连接串只进入受保护的服务端配置。
- 数据库和日志只保存业务需要的数据，不打印微信 code、openid、Token、密码或秘密配置。
- 业务数据库账号使用最小权限，数据库端口不向公网开放。
- 生产数据不用于开发造数或破坏性测试；远端写入始终服从项目授权边界。

## 验收证据

- 自动测试覆盖本次涉及的未登录/合法输入/边界/非法输入/幂等或覆盖行为。
- 生产构建包含本次新增路由、服务和仓储产物。
- 数据库变更有目标身份、迁移完整性和结构核验证据。
- 健康检查只能证明当前依赖可用，不单独证明环境身份、配置完整或发布完成。
