## 1. 通用顺序

先收集四项：错误原文、发生时间、上一项改动、当前阶段。随后只读检查：

```bash
docker ps -a --filter name=<容器名> \
  --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker logs --tail 100 <容器名>
```

不要一开始就删除容器、重建数据库或开放端口。一次只修改一个最可能原因，并重复原验证命令。

## 2. 前端交互与布局

### 加减按钮出现 `null` 或直接跳到上限

WXML 的 `data-*` 在运行时可能是字符串。`100 + "25"` 会拼接，非法拼接参与数值裁剪后可能成为 `NaN` 并显示为 `null`。在事件入口统一使用 `Number` 转换并检查 `Number.isFinite`，不要只修改上下限函数。

### 弹窗底部内容被按钮遮挡或空白过多

先区分“内容自然高度”和“超过屏幕后的滚动高度”。不要把所有弹窗固定为接近 `100vh`。让卡片按内容收缩，对列表设置理想高度和基于视口的 `max-height`，主操作区保持在滚动区之外。

### 日期滚轮的 30 日偶尔保存失败

先检查是否在滚轮惯性滚动尚未结束时点击保存，以及切换月份后“日”列表是否已按新月份重建。用 `bindpickstart` 标记滚动中、`bindpickend` 标记最终落定；月份变化时裁剪日索引并同步受控 `value`。不要用按钮 `disabled` 代替业务校验，否则会丢失用户需要看到的提示。

### 按钮文字在滚动时意外变暗

检查是否把滚动状态直接绑定到了 `disabled` 或非法态样式。滚动状态只负责阻止提交旧值；文字暗色应只绑定到最终业务非法条件，并在 `pickend` 后呈现。

## 3. 开发者工具与自动化

### 提示 `url not in domain list`

若开发电脑直接访问接口正常，问题属于开发者工具合法域名校验。开发期可在本地设置关闭校验并重新打开项目；正式发布必须使用已配置的 HTTPS 合法域名。

### CLI 无法连接或自动化端口不一致

先查看 CLI 帮助和当前开发者工具进程。已运行实例使用不同 HTTP 端口时，先正常退出开发者工具，再用统一 `--port` 打开项目和启用 `auto`。不要并行启动多个实例争用同一项目。

### 自动化端口监听但连接后立即关闭

先精确检查是否有上一次超时遗留的 QA Node 进程。外层 PowerShell 超时不保证子进程退出；多个 QA 会争用连接并交叉覆盖报告。

若没有残留 QA，连接后调用 `systemInfo()` 探活。探活失败说明端口可能是失效渲染进程留下的“假监听”。记录端口所有者，只清理对应自动化渲染进程，再单独执行一次 `cli auto`。不要在旧 WebSocket 上循环连接。

旧版 `miniprogram-automator` 优先由开发者工具自带 Node 18 执行。结束用例使用 `disconnect()`；`close()` 可能关闭自动化上下文并留下不可复用端口。

如果 `Tool.getInfo` 能返回，而 `App.callWxMethod` 或 `systemInfo()` 超时，说明 WebSocket 和 Tool 通道正常，但小程序 App 未挂载。不要继续排查端口或 SDK 版本；正常退出普通 IDE 窗口，等待 3 秒退出确认及主进程结束，再直接用 `cli auto` 启动项目。一个自动化会话只交给一个 QA 客户端，独立探针或失败客户端结束后必须新建会话。

### Windows 健康检查正常但自动化模拟器 `request:fail`

确认本地隧道仍监听且 `urlCheck` 已关闭后，把开发地址从 `127.0.0.1` 尝试切换为 `localhost`。同时打印 `wx.request` 完整失败对象和 `errno`。若只记录 `ApiRequestError` 类名，证据不足，不能据此修改登录或服务端代码。

### 自动化截图与预期状态相同

数据断言后继续等待目标节点出现，再等待 300～500 ms。若不同步骤截图文件大小完全一致，通常是截图早于渲染完成。先修截图等待，不改业务布局。

关键截图增加内容哈希断言。若点击前后哈希相同，应直接判定视觉证据失败；不能因为截图文件存在、业务接口成功，就把弹窗视觉验收标记为通过。

### QA 报告被覆盖或产物持续累积

每次运行写入独立时间目录，完整运行以目录内存在 `report.json` 为准。自动保留最近 3 次完整运行，并清理不完整目录。所有删除必须先解析并验证目标位于项目 QA 产物根目录内，禁止对工作区根目录使用递归删除。

## 4. 镜像拉取

### 镜像标签不存在

证据通常包含 `not found` 或 `failed to resolve reference`。含义是 1Panel 下拉框版本不等于镜像仓库一定存在该标签。

处理：选择同一主要版本中可实际拉取的稳定标签。不要通过换包管理器或改业务代码解决镜像标签问题。

### 下载长时间无变化

先区分“慢”和“停”：观察 5 至 10 分钟内是否仍有新层 `Pull complete`。若确实停止，再检查 ECS 到镜像源的网络、DNS、磁盘空间和镜像加速配置。本机 VPN 通常不会直接改变 ECS 的出口网络。

## 5. 容器退出或重启

`Exited (1)` 或持续重启说明启动命令失败。优先看日志最后一次完整堆栈。常见原因：

- 启动文件不存在；
- 依赖未安装；
- 环境变量缺失；
- 数据库连接失败；
- Node.js 版本不兼容。

不要只根据 1Panel 的“创建成功”判断应用健康。

## 6. 文件与构建产物

### `Cannot find module /app/dist/server.js`

检查顺序：

1. 本地构建是否成功；
2. ZIP 是否包含 `dist/server.js`；
3. 解压是否多出一层目录；
4. 1Panel 项目目录是否指向包含 `package.json` 的目录；
5. Windows ZIP 是否产生异常路径条目。

修复部署包或项目目录后重建运行环境。不要把启动命令改成一个碰巧存在但未经构建验证的文件。

## 7. 端口与健康检查

### `Connection refused`

说明目标端口没有接受连接。检查：容器是否 `Up`、应用是否监听预期端口、`HOST` 是否为 `0.0.0.0`、端口映射是否存在。

### `Connection reset by peer`

通常表示连接建立后进程退出或容器重启。立即查看容器状态和最新日志。

### `/health` 返回 503

应用已启动，但依赖检查失败。优先核对 `DB_HOST`、`DB_PORT`、业务账号密码、数据库名、MySQL 容器状态和 Docker 网络。日志要脱敏。

## 8. 数据库

### `SHOW TABLES` 是空集

确认执行过 `USE <目标数据库>`，导入 SQL 时选择了同一个库，迁移文件本身包含建表语句。

### Node.js 无法连接但宿主机可连接

Node.js 容器中的 `127.0.0.1` 指向 Node.js 容器本身，不是 MySQL。改用 1Panel 显示的 MySQL 容器连接地址。

### 密码不确定

`DB_PASSWORD` 是业务数据库账号密码，不是 Root 密码。面板不显示旧明文时，执行“改密”并同步更新服务端环境变量，然后重启服务。

## 9. SSH 隧道

### 本机无法访问服务端

先确认 ECS 本机 `/health` 正常，再确认 SSH 隧道窗口仍在运行、本机端口未被占用、转发目标是 ECS 的 `127.0.0.1:<端口>`。

推荐 Windows PowerShell：

```powershell
ssh -N `
  -o ServerAliveInterval=30 `
  -o ServerAliveCountMax=3 `
  -L <本机端口>:127.0.0.1:<服务端口> `
  <SSH 用户>@<服务器公网 IP>
```

### 提示私钥口令

`Enter passphrase for key ...` 要求的是本机私钥口令，不是 1Panel 密码或 ECS 密码。输入时无回显属于正常现象。

## 10. 手机真机调试与局域网服务端

### 适用场景

小程序在电脑模拟器中请求服务端正常，但手机真机调试出现 `request:fail net::ERR_CONNECTION_REFUSED`、登录失败或“无法连接服务端”时，先按本节处理。手机里的 `localhost` / `127.0.0.1` 指向手机自身，不是开发电脑；开发电脑本机 `/health` 正常不能证明手机可达。

### 1. 确认手机与电脑在同一局域网

在 Windows PowerShell 执行 `ipconfig`，选择与手机连接同一 Wi-Fi/局域网的真实网卡 IPv4 地址，排除 VPN、虚拟网卡、`127.0.0.1` 和 `169.254.*.*`。手机关闭移动数据或确认路由器没有启用 AP 隔离。

### 2. 将本机 SSH 隧道暴露给局域网

如果测试服务只在远端 ECS 的 `127.0.0.1:<远端端口>` 监听，而开发电脑已有仅回环地址的 SSH 隧道，真机调试使用单独的本机端口，避免与模拟器隧道冲突：

```powershell
ssh -N -g `
  -o ExitOnForwardFailure=yes `
  -o ServerAliveInterval=30 `
  -o ServerAliveCountMax=3 `
  -L 0.0.0.0:<局域网端口>:127.0.0.1:<远端端口> `
  <SSH 配置别名>
```

`-g` 和 `0.0.0.0:<局域网端口>` 只把开发电脑上的转发端口提供给局域网设备；不要因此把 ECS 应用改成公网监听，也不要在日志或回复中输出服务器地址、账号、私钥或密码。

### 3. 从电脑和手机分别验证健康接口

电脑先检查监听和接口：

```powershell
netstat -ano | findstr :<局域网端口>
curl.exe --noproxy "*" --max-time 5 http://<电脑局域网 IPv4>:<局域网端口>/health
```

然后用手机浏览器打开同一个 `/health` 地址。两端都返回应用约定的健康 JSON 后，才进入小程序真机调试。手机打不开时，按“监听地址 → Windows 防火墙 → 手机/电脑是否同网 → 路由器 AP 隔离”的顺序排查；不要先修改登录业务代码。

如果确认仅被 Windows 防火墙拦截，先取得用户授权，再用只允许局域网来源的入站规则：

```powershell
New-NetFirewallRule `
  -DisplayName "MiniProgram LAN debug <局域网端口>" `
  -Direction Inbound -Action Allow -Protocol TCP `
  -LocalPort <局域网端口> -Profile Any -RemoteAddress LocalSubnet
```

测试结束后移除本次临时规则，并保持 SSH 窗口生命周期与测试一致。

### 4. 切换小程序开发 API 地址并重新编译

将开发配置中的服务端基地址从 `http://localhost:<端口>` 或 `http://127.0.0.1:<端口>` 临时切换为：

```text
http://<电脑局域网 IPv4>:<局域网端口>
```

关闭域名校验只解决开发者工具的合法域名检查，不会修复 TCP 连接拒绝。完成真机调试后恢复本机地址，或使用项目已有的私有开发配置/环境变量；不要把个人电脑局域网 IP 提交到体验版或正式版。

### 5. 通过官方微信开发者工具开启真机调试

在服务端健康检查和 API 地址切换完成后，重新编译项目，再使用官方 `wechatide-skill` 的 `automation_viewport_action` `remote` 流程或开发者工具界面的“真机调试”。命令行入口为：

```bash
wechatide -c <clientName> automation_viewport_action --project <project> --action remote --auto
```

若工具返回 `pending`、需要扫码或手机确认，等待当前任务完成后再继续，不要重复发起连接。验收至少记录：

1. 手机 `/health` 可达；
2. 手机小程序能完成微信登录或会话恢复；
3. `console` / `network` 没有新增连接拒绝或未处理异常；
4. 关键页面有手机截图；
5. 测试结束前 SSH 隧道仍保持运行，测试结束后关闭真机调试并恢复开发 API 地址。

### 6. 关闭真机调试并恢复开发环境

1. 手机验收完成后，在微信开发者工具中结束“真机调试”；如由命令行发起，则按当前官方工具任务状态结束，不重复创建新的真机连接。
2. 将小程序 API 地址恢复为原来的本机/开发配置，并重新编译，确认后续模拟器或普通开发流程不再使用电脑局域网 IP。
3. 关闭本次真机调试专用的 SSH 隧道窗口。
4. 如果为本次测试新增了 Windows 防火墙规则，只删除这条临时规则；不要误删项目或系统已有规则。

### 常见分流

- 电脑 `localhost` 正常、手机 `ERR_CONNECTION_REFUSED`：优先检查 API 是否仍是 `localhost`、SSH 隧道是否只绑定回环地址、局域网端口和防火墙。
- 手机浏览器 `/health` 失败：问题在局域网、监听或防火墙，不修改微信登录代码。
- 手机 `/health` 正常但小程序失败：确认重新编译生效、API 路径无旧缓存，并打印完整 `wx.request` 失败对象和 `errno`。
- 出现 `url not in domain list`：这是合法域名校验问题，按第 3 节处理；它与 `ERR_CONNECTION_REFUSED` 不是同一层级。

## 11. 微信登录

### 前端提示“无法连接服务端”

先在开发电脑执行 `/health`。若失败，问题在隧道或服务端，不要修改微信登录代码。

若开发电脑 `/health` 正常，但开发者工具提示 `url not in domain list`，按第 3 节处理合法域名校验。

### 服务端可达但登录失败

按顺序核对：

1. 开发者工具 AppID 与服务端 `WECHAT_APP_ID` 是否一致；
2. AppSecret 是否来自同一测试号；
3. 环境变量修改后服务是否重启；
4. 服务端是否能访问微信接口；
5. code 是否只使用一次且未过期；
6. 服务端脱敏日志中的微信错误码。

不要让用户展示 AppSecret 或完整 code。

## 12. 会话验收

重复登录后会话数量不增加时，先确认前端是否真的清除了本地 Token 并再次调用登录接口，再检查服务端是否采用“复用会话”策略。会话数量是否增加取决于产品设计，必须先确认策略，不能把某一种结果绝对化。

安全核验只显示统计值：

```sql
SELECT COUNT(*) AS totalSessions,
       SUM(CHAR_LENGTH(token_hash) = 64) AS hashedSessions
FROM user_sessions;
```

`totalSessions = hashedSessions` 只能证明字段长度符合预期，还应结合代码审查或测试确认写入前确实使用 SHA-256。

## 13. JSON 请求或响应体为空

遇到 `Body cannot be empty when content-type is set to application/json` 时，先确定错误发生在请求侧还是响应侧，不要仅凭接口状态码判断：

1. 检查客户端实际发送的请求方法、请求头和请求体；
2. 检查服务端实际返回的状态码、响应头和响应体；
3. 确认请求与响应各自的 `Content-Type` 是否与对应 Body 匹配。

如果 `wx.request` 的非 GET 请求使用 JSON Content-Type 且没有业务参数，应显式发送 `{}`。如果接口返回 `204 No Content`，响应不得再声明 JSON 响应体；如果客户端公共封装固定解析 JSON，可改用明确的 `200` JSON 成功响应，但应保持接口契约、服务端实现和客户端解析规则一致。
