# Figma 与前端实现

## Figma 读取

- 从用户 URL 提取 file key；先用元数据定位具体画板，再读取具体节点设计上下文。
- 调用 `get_design_context` 前加载 `figma-design-to-code` Skill。
- 将返回的 React/Tailwind 参考转换为项目现有 WXML、WXSS、TypeScript，不安装 Tailwind。
- 用户最新规则优先于 Figma；对删除、隐藏或改变的设计项留下文档说明。

## 原生小程序实现

- 复用项目已有页面、文案配置、API 封装、类型和视觉变量。
- 保存后使用服务端响应刷新状态，避免前后端计算漂移。
- `wx.request.fail` 保留原始 `errMsg`，方便判断域名、网络或隧道问题。
- WXML `data-*` 按字符串处理；数值计算前用 `Number` 转换并检查 `Number.isFinite`。
- 日期滚轮切换年月时重新计算有效日期，并在前后端重复校验边界。
- 弹窗按内容自然收缩；超过屏幕才滚动，主操作区不得遮挡最后一项。
- `picker-view` 动态重建日列表时，用 `bindpickstart`/`bindpickend` 区分滚动中与最终值；滚动中不得提交可能仍在变化的日期。
- “非法但仍需点击后提示”的按钮不要设置原生 `disabled`；用独立状态类改变文字颜色，保留点击事件执行校验提示。
- 把滚动状态、保存中状态和业务非法状态分开建模，避免滚动时意外触发禁用色或非法态样式。
- 卡片多行摘要使用结构化数据组合，并同时配置换行渲染和最大行数；不要把服务端展示文案当作唯一业务数据。

## 本地验证

- 运行项目现有 TypeScript、Lint、构建或静态检查；
- 检查 WXML 绑定、事件名、滚动区和 WXSS 结构；
- 验证空态、默认值、上下限、保存中、成功、失败和重新进入回显；
- 准备 375、390、430 逻辑宽度及常见屏幕高度的 QA 用例。
