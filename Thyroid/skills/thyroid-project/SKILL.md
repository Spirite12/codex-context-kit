# 甲状腺微信小程序项目导航

## 核心职责

本 Skill 只负责甲状腺项目的资料定位、项目 override 和项目特有流程。通用微信小程序需求分类、前后端实现、微信模板字段门禁、服务端/数据库通用安全和开发者工具编排使用系统级 `wechat-miniprogram`。

不要把 `docs/` 中的产品、UI、技术事实复制进 Skill；不要把已经由代码表达的尺寸、端口计算、Canvas 参数等实现细节长期保存在 Skill。

## 硬边界来源

根 `AGENTS.md` 是本项目环境身份、生产数据、授权、微信提审和敏感信息边界的唯一权威入口；本 Skill 不再复制这些规则。执行环境、部署或发布步骤时仍读取对应 reference 的操作门禁；若 reference 与根规则冲突，以根 `AGENTS.md` 为准。

## 开始任务

1. 读取根 `AGENTS.md`。
2. 确定任务类型、范围、排除项和成功标准。
3. 只读取当前任务需要的项目事实和 reference；需要当前状态或历史证据时再读取 `docs/开发记录.md`，不为普通任务默认加载全部历史。
4. 检查相关代码、配置、迁移和测试，以当前实现为事实，不用旧对话代替。
5. 新增功能或产品规则变化先完成根 AGENTS 中的主类判断和隐私影响判断，再按系统 `wechat-miniprogram` 的任务分类进入策划。
6. 已确认方案的实现、明确缺陷、环境切换、配置核对或文档整理不重复走完整策划；只有新发现会改变产品、数据、安全、成本或授权范围时再询问。

## 项目事实路由

- 产品范围与业务规则：`docs/策划案.md`
- UI 视觉或交互：必须读取 `docs/UI规范.md`；如果无法读取，停止 UI 设计、实现或验收
- 当前技术实现、接口、数据、架构：`docs/技术设计.md`
- 已发生结果与验收证据：`docs/开发记录.md`
- 未完成事项：`docs/待办清单.md`

- 隐私影响：`docs/隐私政策基线.md`
- Figma/前端：相关 `miniprogram/` 代码 + 策划/UI 规范 + 实际 Figma 节点
- 服务端/数据库：`server/src/`、`server/migrations/`、`server/tests/`、服务端 package/lock 文件

- 生产/隔离环境身份、数据库迁移、部署队列、备份与回滚：`references/生产部署与数据库门禁.md`
- 开发者工具 targeted/full/skip QA：`references/微信开发者工具QA.md`

只加载当前阶段需要的 reference。

## 默认开发闭环

用户说“开始开发”“按开发流程完成”或“完成该功能”时，按影响范围推进：

```text
需求与现状核对
→ 适用的前端 / 服务端 / 数据实现
→ 相关 Review、类型检查、自动测试、构建
→ 项目默认 targeted 开发者工具 QA
→ 更新对应事实文档与结果账本
```

- 不涉及的层级标记为“不适用”，不要主动扩建。
- 自动 QA 通过不等于用户人工验收通过；真机、真实微信授权、体验版和正式发布分别记录。
- 线上生产迁移或服务端/配置部署不属于默认开发闭环。
- 同一失败层级最多自动修复并重测两轮；仍失败时停止并报告阻塞证据。

## 版本公告

`docs/版本.md` 是版本公告维护来源；小程序运行时使用 `miniprogram/config/version-history.ts` 或等效构建数据。修改公告时核对两者一致，不让客户端运行时直接读取仓库 `docs/`。

公告标题、内容等产品规则以 `docs/版本.md` 和策划案为准；不要把具体版本内容复制进 Skill。

## 完成与输出

- 产品规则变化更新策划案；接口、数据或架构变化更新技术设计；UI 长期规范更新 UI 规范；未完成事项写待办；开发记录只写结果、验证层级和必要证据入口。
- 已由代码表达的实现参数不重复写入 Skill；跨项目通用且容易造成数据/安全事故的规则提炼到系统级 Skill。
- 最终回复保持简短：说明实际结果、必要核心标识、阻塞或用户可能误认为已完成但实际未执行的关键阶段。
