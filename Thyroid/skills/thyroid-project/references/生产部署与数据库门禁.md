# 生产部署与数据库门禁

## 环境身份

- `thyroid-ecs` 是线上生产 ECS。
- 远端业务数据库 `thyroid` 是线上生产数据库。
- 本地开发数据库为 `thyroid_local`。
- 当前没有登记为可默认使用的隔离测试 ECS。
- `ops/deploy-queue/` 的目录名、历史 `environment: "test"`、SSH 别名或 `/health` 成功均不能证明目标是隔离测试环境。

## 授权边界

以下动作分别授权，不相互继承：

- 生产只读查询；
- 生产数据库迁移；
- 生产服务端/运行配置部署；
- 微信代码上传/体验版；
- 正式发布。

“合并 main”“开始全流程”“部署一下”或已经连接 SSH 都不是生产写入授权。

生产业务数据默认只读。除正常线上业务外，开发、测试、排障、迁移验证或脚本不得造数、修正、清空或批量回填生产业务数据。

## 隔离测试目标

只有同时确认独立主机/容器、独立数据库、环境身份标记和对应健康检查后，才可把目标视为隔离测试环境。当前未登记此类目标，因此默认停在本地。

未来若建立隔离测试环境，`ops/deploy-queue` 只能在目标身份、数据库名和用户授权全部匹配后启用；历史任务不能自动复用为新环境证明。

## 数据库迁移

对已核验的隔离测试环境或经单独授权的生产环境：

1. 核对本地迁移编号与目标结构/迁移记录，不能只检查本次新增迁移；
2. 迁移前备份并确认回滚路径；
3. 按编号执行缺失迁移；
4. 核对字段、索引、约束和必要字符集；
5. 包含中文或非 ASCII 数据时遵循系统级 `wechat-miniprogram` 的 utf8mb4 门禁并抽查实际文本；
6. 应用 `/health` 不能替代迁移完整性证明。

已执行迁移不原地改写；修复使用新迁移。

## 服务端与配置部署

只有用户明确授权生产服务端/配置部署时才执行。部署前至少具备：

- 本地受影响代码 Review；
- 相关类型检查、自动测试和生产构建；
- 本版本需要的迁移与运行配置清单；
- 备份和旧产物回滚依据；
- 目标环境身份核验。

部署后核对实际运行产物、必要配置存在性、应用/数据库健康状态和本版本微信能力就绪状态。不要把“容器 Up”当作完整成功。

不得为了快速修复从对话临时绕过项目安全门禁，直接覆盖生产 `.env`、替换未知远端文件或执行任意 SQL。

## 队列

当前隔离测试部署队列视为封存，不得用于 `thyroid-ecs` 或数据库名 `thyroid` 的目标。

若未来明确建立隔离测试目标，迁移和服务端产物按项目现有队列协议顺序执行；失败、阻塞或心跳异常时暂停，人工核对备份、目标和健康状态后再按工具提供的 resume/retry/discard 操作处理，不用更新快照跳过缺失迁移。
