# 微信开发者工具 QA 规则

## 1. 职责

- 系统级 `wechat-miniprogram` 负责选择 QA 模式、组织测试和判定验收关卡；
- 官方 `wechatide-skill` 负责打开/编译项目、操作模拟器、读取 console/network 和截图；
- 本文件只定义甲状腺项目测什么、怎样算通过以及如何保存证据。

## 2. QA 模式

| 模式 | 执行范围 | 选择规则 |
| --- | --- | --- |
| `targeted` | 本功能定向测试 | 本项目默认 |
| `full` | 定向测试 + 安全固定回归 | 用户明确要求 |
| `skip` | 不进入开发者工具 QA | 用户明确要求跳过 |

未执行范围必须记录为未执行/豁免，不得写成通过。涉及登录、公共请求层、首页公共状态或数据契约的高影响改动，在不执行固定回归时说明风险。

## 3. QA 前置

1. 完成本次改动对应的本地类型检查、自动测试和构建。
2. 需要服务端时读取 `环境切换与本地联调.md`，确认当前模式和数据库身份；本地 QA 必须使用本机服务与 `thyroid_local`。
3. 本地 `/health` 失败时排查本地链路，不得自动通过 SSH 改连 `thyroid-ecs`。
4. 定义本功能用例的目标、前置条件、步骤、断言、截图点和数据影响。
5. 涉及真实授权、上传或其他外部变化时遵守对应独立授权边界。

开发者工具“服务端口”是 CLI 接入开关，不是项目 API 端口。

## 4. 定向测试

至少覆盖：

```text
用例 ID
目标
前置条件
步骤
断言
截图点
数据影响
```

覆盖正常态，以及适用的空态、边界态和服务端错误态。持久化功能验证保存后重新进入回显。无法稳定构造的状态记录为未执行或人工验收，不虚构通过。

## 5. 安全固定回归

仅 `full` 模式执行：

- `REG-01`：项目编译与个人中心加载，无未处理编译、运行时和 Promise 错误；
- `REG-02`：登录状态恢复符合现有设计，未登录不静默授权。

本次改动涉及保存逻辑时，把完整保存流程放入定向测试；固定回归优先复用已有安全测试数据。需要覆盖数据或触发不可逆状态时先取得授权。

## 6. 官方 Skill 顺序

1. 按 `wechatide-skill` 门禁检查版本、登录和令牌；
2. 首次 CLI 授权无弹窗时，检查开发者工具是否启动以及“设置 → 安全设置 → 服务端口”；
3. 使用 `initializer` 打开项目并读取运行时上下文；
4. 使用 `compiler` 编译/刷新目标页；
5. 使用 `automator` 执行定向用例；只有 full 才继续固定回归；
6. 使用 `debugger` 收集 console/network 和关键截图；
7. 汇总结果并写入本轮证据目录。

真机调试的 API 模式和局域网/非局域网入口不在本文手工修改，统一读取 `环境切换与本地联调.md`。真机调试结束后恢复常用本地模式。

## 7. 有限修复

失败分为环境、编译、自动化、网络、业务、测试数据和证据。第一次失败只修当前层级最小问题并重跑失败/相邻用例；同一失败层级第二轮仍失败时停止，不继续重启、重连或猜测修改。

首次扫码、授权、项目确认和真机操作只请求用户完成当前必要步骤。

## 8. 证据

每轮产物保存到 `automation/artifacts/<scope>/<run-id>/`，至少包含：

```text
report.json
console.log
network.log
screenshots/
```

`report.json` 记录 QA 模式、范围、用例结果、未执行/豁免项、失败层级、数据影响和证据路径。只在所选模式要求的用例通过、没有未处理错误且关键截图有效时标记 QA 通过。

每个 scope 维护 `latest.json`，默认只保留最近三次完整运行；删除仅限当前 scope 产物目录。
