# 微信开发者工具 QA 规则

## 1. 职责

- 系统级 `wechat-miniprogram` Skill 负责选择 QA 模式、组织测试和判定验收关卡；
- 官方 `wechatide-skill` 负责打开与编译项目、操作模拟器、执行页面自动化、读取 console/network 和截图；
- 本文件定义甲状腺项目测什么、怎样算通过以及如何保存证据。

## 2. QA 模式

| 模式 | 执行范围 | 选择规则 |
| --- | --- | --- |
| `full` | 本功能定向测试 + 安全固定回归 | 用户明确要求时 |
| `targeted` | 仅本功能定向测试 | 本项目默认 |
| `skip` | 不进入开发者工具 QA | 用户明确要求跳过时 |

`targeted` 模式下固定回归记录为“未执行/项目默认 targeted”；`skip` 模式下所有开发者工具 QA 记录为“未执行/用户豁免”，不得记录为通过。涉及登录、公共请求层、首页公共状态或数据契约的高影响改动，在不执行固定回归前说明回归风险。

## 3. 定向测试用例

开发完成后，先根据需求和实际实现填写以下内容：

```text
用例 ID：FEATURE-001
目标：本次功能要证明的结果
前置条件：登录态、测试数据、页面路径和服务端状态
步骤：按顺序列出用户操作
断言：页面、数据回显、接口及错误状态的通过标准
截图点：关键状态和失败时最后画面
数据影响：无 / 复用现值 / 会新增或覆盖测试数据
```

至少覆盖本次功能的正常态、适用的空态或边界态、服务端错误态，以及保存后重新进入的回显。无法稳定构造的状态应记录原因和人工验收项，不得虚构通过。

## 4. 安全固定回归

仅当用户明确选择 `full` 模式时，执行下列不主动破坏真实测试数据的核心回归：

| 用例 ID | 范围 | 通过标准 |
| --- | --- | --- |
| `REG-01` | 项目编译与个人中心加载 | 模拟器可进入个人中心；无未处理编译、运行时和 Promise 错误 |
| `REG-02` | 登录状态恢复 | 已登录测试号可恢复个人资料；未登录时只展示主动登录入口，不静默授权 |

若本次改动触及某项保存逻辑，该项完整保存与重新进入回显应放入定向测试；固定回归复用现有有效值，不为回归随意重置数据库。需要覆盖真实测试数据或执行签到时，先取得明确授权，并在交付记录中写明最终数据状态。

## 5. 官方 Skill 执行顺序

1. 按 `wechatide-skill` 门禁检查版本、登录和令牌状态；
2. 首次需要 CLI 连接时，确认微信开发者工具已启动，并按下方“CLI 授权弹窗预检”处理服务端口；
3. 需要项目服务端时，先按下方“项目服务端连接预检”确认本地隧道与健康状态；
4. 使用 `initializer` 打开项目并读取运行时上下文；
5. 使用 `compiler` 编译或刷新目标页；成功触发刷新不等于编译通过；
6. 使用 `automator` 执行定向测试；仅当用户明确选择 `full` 模式时，继续执行固定回归；
7. 使用 `debugger` 收集 console、network 和关键截图，检查未处理异常；
8. 汇总结果并写入本轮产物，必要时更新开发记录。

### CLI 授权弹窗预检

如果预期出现“Codex 请求连接”但首次授权尝试没有弹窗，不要连续等待到多轮超时，先把问题归类为环境连接门禁：

1. 检查微信开发者工具是否已启动，以及“设置 → 安全设置 → 服务端口”是否开启；
2. 若官方工具支持安全读取或设置服务端口，先询问用户“是否允许我帮你开启服务端口”，获得同意后再操作；
3. 若当前工具不能代为设置，立即提示用户打开“微信开发者工具 → 设置 → 安全设置 → 服务端口”，开启后回复“已开启”；
4. 用户处理后重新执行一次状态检查或授权，不重复此前已通过的业务步骤。

此“服务端口”是微信开发者工具的 CLI 接入开关，不是项目 API 使用的本机 `3000` 端口。沟通和报告必须使用完整名称区分两者。

### 项目服务端连接预检

先在 Windows PowerShell 执行：

```powershell
Invoke-RestMethod http://localhost:3000/health
```

若失败，优先由 Agent 使用以下项目固定参数启动隐藏后台 SSH 进程，并再次执行健康检查：

```powershell
ssh -N -L 3000:127.0.0.1:3000 thyroid-ecs
```

- `thyroid-ecs` 只是本机 SSH 配置别名；不得把别名对应的真实地址、账号、密码或密钥写入 Skill、日志和报告；
- 隧道命令本身会持续运行。Agent 自动处理时应启动隐藏后台进程，不占用用户当前终端；
- 若遇到密码、密钥解锁、首次主机信任或权限确认，立即停止自动重试，直接把上述隧道命令和健康检查命令一起发给用户；用户完成后继续原 QA；
- 首次失败产生的历史 console 日志应保留并标记为“已恢复的前置故障”，不得误报为最终功能错误；恢复后仍有新增网络或业务错误时，才按失败止损规则处理。

### 真机调试 API 配置（本项目固定规则）

- 真机调试时，只需要修改 `miniprogram/config/api.ts` 中的 `API_BASE_URL` 值。
- 将 `API_BASE_URL` 从 `http://localhost:3000` 临时改为 `http://<电脑局域网 IPv4>:<局域网端口>`；不修改 `API_PATHS`、请求封装、微信登录逻辑、服务端代码、`project.config.json` 或 `project.private.config.json`。
- 真机调试结束后，将 `API_BASE_URL` 恢复为 `http://localhost:3000`，再重新编译；不得把电脑局域网 IP 提交到体验版或正式版。

## 6. 有限修复与停止条件

- 将失败归类为环境、编译、自动化选择器、网络、业务断言、测试数据或截图；
- 第一次失败后只修复当前层级的最小问题，并重跑失败用例及相邻用例；
- 同一失败层级第二轮仍失败时立即停止，不继续重启、重连或猜测修改；
- 停止时记录失败步骤、最后成功步骤、日志、截图、已尝试修复和下一步；只有用户明确要求继续或提供新信息后才开始新一轮；
- 首次扫码登录、授权、项目确认和真机操作只请求用户完成当前必要步骤。

## 7. 证据与状态

每轮产物保存到 `automation/artifacts/<scope>/<run-id>/`：

```text
report.json
console.log
network.log
screenshots/
```

`report.json` 至少包含 QA 模式、功能范围、用例结果、未执行/豁免项、失败层级、数据影响、开始结束时间和证据路径。成功与失败运行均生成报告；仅所有已要求用例通过且没有未处理错误时，才将 QA 标记为通过。

每个 scope 维护 `latest.json`，只保留最近三次生成了 `report.json` 的完整运行。不完整目录在下一轮清理；删除范围只能位于对应的 `automation/artifacts/<scope>/` 内。
