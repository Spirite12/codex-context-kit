# 甲状腺微信小程序项目约定

## 项目边界

- 项目由原生微信小程序、Node.js/Fastify 服务端、MySQL、本地开发链路和经独立核验后才能使用的隔离测试/生产发布链路组成；当前仓库没有可默认使用的隔离测试 ECS。
- 后续每次新增需求进入策划阶段时，先读取项目根目录 `project.metadata.json` 的 `wechat.mainCategory`。仅当该字段存在且非空时，才判断新增需求是否服务于当前微信平台主类及现有甲状腺健康管理目标；字段不存在或为空时，明确说明本次跳过主类判断，不得自行推断或补写主类。
- 修改前确认需求范围、排除项、数据归属和成功标准，只做与当前请求直接相关的最小改动。
- 通用开发、部署、安全和排障流程使用系统级 `wechat-miniprogram` Skill。
- 项目资料定位和按需读取使用项目级 `thyroid-project` Skill。

## 环境身份与数据库硬门禁

- 当前已确认：SSH 别名 `thyroid-ecs` 指向线上生产 ECS，远端业务数据库 `thyroid` 属于线上正式数据。不得再把它称为“测试 ECS”“测试库”或默认测试环境。
- 本地开发/验证只使用本机服务和 `thyroid_local`；本地 `/health`、静态检查、自动测试或开发者工具模拟器通过，均不能证明远端是隔离测试环境。
- 隔离测试环境必须有独立主机或独立容器、独立数据库目标、可追溯的配置身份，以及与目标数据库一致的只读 `/health` 证据；在这些信息没有逐项确认前，远端迁移、服务端部署、造数和验证写入一律停止在本地。
- `ops/deploy-queue/` 中历史 manifest 的 `environment: "test"`、队列目录名称或“测试环境”文字不是环境身份证明；执行前必须核对真实目标，不得由任务名推断数据库归属。
- 用户说“合并到 main”只授权 Git 检查/合并范围，不授权远端查询、数据库迁移、服务端部署、微信上传或发布；这些动作仍需单独授权。

## 新增需求主类判断

- 当 `project.metadata.json` 的 `wechat.mainCategory` 已配置时，策划阶段在分析每个新增需求时，必须明确输出以下判断：
  - 判断依据：读取到的微信平台主类；
  - **属于主类**：直接支持已读取的微信平台主类，且与当前策划案定义的甲状腺健康管理目标一致，可以继续进入策划；
  - **边界待确认**：能够间接支持健康管理，但会明显扩展用户、场景、数据或业务范围，必须先说明扩展点并由用户确认；
  - **超出主类**：与健康管理目标缺乏直接关系，或会形成独立产品、独立业务或新的产品主类，应明确提示超出范围，不得直接开始设计或编码。
- 判断时至少说明：需求解决的用户问题、与已读取微信平台主类的关系、对现有产品边界的影响，以及判断结论和理由。
- 若未读取到有效的 `wechat.mainCategory`，只按现有策划案和其他项目边界分析需求，不执行上述主类归属判断，并在回复中明确标注“主类未配置，已跳过主类判断”。
- 若用户确认纳入“边界待确认”或“超出主类”的需求，先更新 `docs/策划案.md` 中的产品定位、功能范围或排除项；涉及接口、数据或架构时再同步 `docs/技术设计.md`，确认后的策划才能进入实现。
- 未完成上述判断和必要的产品确认前，不得从新增需求直接跳到技术方案、代码实现或测试安排；未确认的想法先记录到 `docs/待办清单.md`。

## 新增需求隐私影响判断

- 每个新增需求进入策划阶段时，在主类判断后，检查是否改变个人信息或医疗健康数据的收集、使用、存储、共享、删除、授权或用户权利，并判断隐私政策及微信后台配置是否需要更新。
- 首次检查不要求用户提供隐私政策全文；需要逐条比对或修改具体文案时，再提供当前政策文本、截图、链接或后台配置。若涉及政策或配置变化，先完成产品范围确认并更新相关文档，未确认前不得编码或发布。

## 事实来源

- 产品范围与业务规则：`docs/策划案.md`；
- UI 视觉与通用交互规范：`docs/UI规范.md`；
- 当前技术实现：`docs/技术设计.md`；
- 当前状态与历史证据：`docs/开发记录.md`；
- 当前待办与未确认想法：`docs/待办清单.md`；
- 版本公告内容：`docs/版本.md`；
- 隐私基线：`docs/隐私政策基线.md`。涉及新增或变更个人信息处理的需求时先读取该基线，再核对产品、技术和实际代码，并与微信后台最新页面或截图比对；微信后台实际生效版本优先。

## 文档写入边界

- `docs/策划案.md`：只写已确认的产品目标、功能范围、业务规则、用户可见交互和排除项；不维护当前开发状态、发布门禁、测试过程或部署步骤。
- `docs/UI规范.md`：只写跨页面可复用的视觉基线、组件规范、设计来源和通用交互；页面业务条件仍回到策划案，具体实现参数以代码为准。
- `docs/技术设计.md`：只写当前有效的架构、接口、数据结构、技术边界和运行基线；环境切换、部署、发布和 QA 的执行步骤放到项目 Skill references，不在技术设计重复维护。
- `docs/开发记录.md`：作为精简结果账本，只保留已经发生且仍有追溯价值的结果、验证层级和必要证据入口；不记录逐步过程、命令流水、完整日志、重复产品规则或当前待办。
- `docs/待办清单.md`：只写尚未完成的功能想法、验收、配置、部署或发布动作；已确认规则和已完成实现不在待办重复描述。
- `docs/版本.md`：只维护版本号、公告标题和该版本交付内容；历史条目不作为当前产品或技术事实来源。
- `docs/隐私政策基线.md`：只维护当前隐私处理事实、微信后台核对快照和待核对差异；“什么时候读取、如何更新”的流程由本文件和项目 Skill 约束，不在隐私文档重复维护。

### 文档同步规则

- 产品规则发生变化：先更新策划案；如果影响接口、数据或架构，再同步技术设计；开发记录只补充实际变更和验证结果。
- 接口、数据或架构发生变化：更新技术设计；完成验证后在开发记录补充证据；不要把技术方案长期只留在开发记录中。
- 新想法或未确认需求：先写待办清单，不得直接写成策划案中的确定规则。
- 新增待验收、待配置、待部署或待发布事项：写待办清单；完成后移除待办，并在开发记录留下完成证据。
- 文档内容冲突时，产品规则以策划案为准，当前技术实现以技术设计为准，未完成事项以待办清单为准，历史过程和验收证据以开发记录为准。

## 工程规则

- 使用中文沟通和编写文档，代码文件使用 UTF-8；
- 遵循现有架构、命名、代码风格和测试方式；
- 前端与服务端都校验业务输入，服务端是最终数据边界；
- 所有自然日业务统一使用 `Asia/Shanghai`；
- 不输出或提交 AppSecret、密码、私钥、Token、`openid` 或完整公网 IP；
- 本地、隔离测试环境与线上生产发布分开；上传、提审、正式发布以及任何线上数据库写入必须另行获得明确授权。
- 小程序已上线，线上正式数据库的内容属于生产数据；除线上正常业务运行所必需的应用写入外，任何开发、测试、排障、脚本、迁移、部署或验证操作均不得新增、修改、删除、清空、批量回填或修正数据库内容，默认只允许只读查询。需要造数或验证写入时，必须使用独立测试数据库或脱敏副本；数据库结构迁移仍须另行遵守授权、备份、历史完整性核对和回滚规则，不得借此改变业务数据内容。

## 运行环境与发布授权

- 默认开发与验证使用本机服务和 `thyroid_local`；环境切换、模拟器、同局域网真机和非局域网真机的固定流程读取 `.agents/skills/thyroid-project/references/环境切换与本地联调.md`。网络不通不得自动回退到 `thyroid-ecs`。
- `thyroid-ecs` 与数据库 `thyroid` 属于生产环境。生产只读查询、数据库迁移、生产服务端/配置部署、微信代码上传、体验版、正式发布分别受独立授权约束；任何前置阶段完成都不自动授权下一阶段。
- 微信提审由用户在微信后台人工执行；Agent 只做提审前检查并等待用户反馈审核结果，不代替用户提交审核。
- 正式发布流程、微信能力功能就绪检查和发布后的版本通知询问读取 `.agents/skills/thyroid-project/references/微信能力与发布.md`。
- 生产部署、数据库迁移、部署队列、备份与回滚读取 `.agents/skills/thyroid-project/references/生产部署与数据库门禁.md`。
- 用户说“合并到 main”只授权 Git 检查与合并，不授权远端查询、部署、微信上传、提审或发布。

## 多 Agent 调度

本项目仅在任务命中下表中的多 Agent 调度场景时，才可按项目规则主动启用多 Agent；未命中时不主动调度。除非用户明确指定其他模型或 effort，否则按以下默认值执行；用户的明确指定优先于本表。

本项目的多 Agent 调度须遵守全局根 Agent 单层调度约束；本节仅定义本项目的调度场景及默认模型/effort。

| 任务场景 | 默认模型 | 推理强度 |
| --- | --- | --- |
| 首次打开微信小程序，需要连接服务端或建立本地服务端连接链路 | `gpt-6-luna` | `xhigh` |
| 微信小程序真机联调，需要连接服务端或排查真机服务端连通性 | `gpt-6-luna` | `xhigh` |
| 图片生成或编辑任务 | `gpt-6-sol ` | `low` |
| 图片读取或分析任务 | `gpt-6-sol ` | `low` |
| 策划案阶段，包括需求分析、跨前后端影响分析、技术方案评审和策划确认 | `gpt-6-sol ` | `medium` |
| 完整执行项目开发流程，包括前端、后端、数据库迁移、部署和 QA 验证 | `gpt-6-luna` | `max` |

当任务命中完整开发流程时，优先使用该行的模型与 effort；其中包含的策划、数据库迁移、历史完整性核对、回滚评估、部署和 QA 子阶段，不再单独触发其他模型路由。只有用户明确限定为独立子任务时，才使用其他对应路由。

模型和 effort 仅表示默认调度路由，不替代任务本身所需的授权、确认、备份、测试或发布边界。实际发起调度时，遵循系统级“多 Agent 调度”菜单的回执要求；模型或 effort 不可用时，不得静默替换。

## 验证与文档

- 非平凡改动至少执行相关类型检查、自动测试和生产构建；涉及迁移或部署时补充备份、结构核验和健康检查证据；
- 开发者工具 QA 默认使用 `targeted` 模式，仅执行本次功能定向测试；用户明确选择 `full` 时才执行项目固定回归，选择 `skip` 时跳过开发者工具 QA；未执行部分必须如实记录，不得声明通过；
- 开发者工具操作使用官方 `wechatide-skill`，项目测试范围、断言和证据要求以 `.agents/skills/thyroid-project/references/微信开发者工具QA.md` 为准；同一失败层级最多自动修复并重测两轮，仍失败时停止并报告证据；
- 产品规则变化更新策划案，接口/数据/架构变化更新技术设计，进度和验收证据更新开发记录；
