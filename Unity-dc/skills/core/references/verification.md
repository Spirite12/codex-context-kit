# 审查与验证

## 阅读范围

- 普通任务只读关联模块；用户要求全工程审查时，列出所有项目源码、工具、配置、文档及资源清单，再按模块阅读。
- Library、Temp、Logs、obj、IDE 缓存及构建产物不是源码范围；查编译环境或包 GUID 时可定向读取必要元数据，说明例外用途。
- 插件只核对 manifest、程序集、版本说明及项目接入位置，不默认深入实现。
- Unity YAML 资源检查挂载、GUID 和配置；图片、音频等二进制只列清单或按需预览。明确区分文本审查、机器扫描、视觉检查，不把它们统称为全部运行验收。
- 以 `git status --short`、`git ls-tree HEAD Assets/DCFrame`、`git -C Assets/DCFrame rev-parse HEAD` 和子模块自身状态核对基线；Git shell 包装命令失败时可使用这些直接命令。

## 风险对应的验证

| 改动 | 最小有效证据 |
| --- | --- |
| Skill 文档/索引 | 引用路径核对、Skill 自检、diff 检查；说明自检仅作路由 |
| Python 批处理辅助脚本 | 语法检查、参数与前置条件失败路径、dry-run 不启动子进程；记录未实际执行 Unity |
| 纯 C# 算法 | 项目现有测试；若用独立桩复现，说明与 Unity 环境的差别 |
| 运行时/程序集 | Unity 编译；涉及 Editor API 隔离时核对 Player 编译，不能只用 Editor csproj 判断可打包 |
| 配表/本地化生成 | 隔离输出差异、失败传播、重跑结果、自定义内容保留与运行时读取 |
| UI/异步资源 | 成功、失败、重复进入、加载中销毁/关闭、释放次数；资源挂接与表现由开发者验收 |
| 热更 | 本地包、旧 Catalog、下载失败、重试与版本兼容；发布授权与本地检查分开 |

在仓库根运行 `python .agents/scripts/skill_self_check.py`。需要定位规则时追加 `--path <路径>`；它会替代自动收集，必须传完整的待审范围。`--strict` 只判断相关文档是否有改动，不校验文档事实。

批处理示例：`python .agents/skills/core/scripts/run_unity_task.py table --unity-path "<匹配项目版本的 Unity.exe>" --dry-run`。此步骤仅检查命令和静态前置条件。去掉 dry-run 会真实修改生成资产；先检查专题中的删除/覆盖边界。项目已在 Editor 打开时不另启同目录 batchmode。

## 交付

- 报告实际修改、命令/退出码、未执行原因及最小人工验收项。
- 审查问题附文件位置、触发条件、影响、最小建议；区分静态确认、实测复现、待验证风险、模板占位和产品能力建议。
- 没有现有测试或 CI 时如实说明；不要为了通过自检而运行无关生成、构建或上传。
- 具体缺陷清单属于审查交付，不把一次审查的全部问题永久堆入 Skill。Skill 只保留会影响后续操作决策的限制，并在对应实现修复后删除过期限制。
